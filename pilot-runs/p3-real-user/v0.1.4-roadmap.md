# Phase D — Lifecycle-Robustheit (~5-6h)

## D.1 PB-009 Drift-Plausibility-Check (~3h)

**Source-Files:** `commands/bridge-handover.md` + `tools/bridge_state.py`

**Driver:** p3-Empirie drift_factor 2.4 für Pre-Mapping-Phase als signifikant; bridge-Plugin sollte Drift-Werte plausibility-checken vor Persistierung.

**Patch:**

bridge-handover bei type=verify oder type=execute mit `actual_min`-Wert berechnet `drift_factor = actual_min / estimated_min`, prüft gegen Memory-historische Drift-Range pro Pair-Topic-Pattern. Bei Abweichung > 2×Std-Dev: WARN-Marker + Empfehlung manuelle Stichprobe.

**Empirie-Anker:** p3-drift_factor 2.4 (Pre-Mapping) + 1.14 (Mapping) als Reference-Range.

**Self-Test:** T40-T41.

## D.2 PB-002 Anti-Endless-Loop Reflection-Action-Ratio (~3h)

**Source-Files:** `commands/bridge-status.md` + `tools/bridge_state.py` + Skill-Body-Patches

**Driver:** ADR_0029 spezifiziert max 3 CAS-Retries, aber kein Schutz gegen iterate↔execute-Pingpong oder counter↔re-sync-Endlos-Schleifen. p3-Klarstellungs-Pauses (R13/R17) als Empirie-Indikator dass Pair-Negotiation-Inflation real ist.

**Patch:**

bridge-Plugin berechnet pro Pair Verhältnis:
```
ratio = count(rounds[type ∈ {counter, re-sync, status, question}])
      / count(rounds[type ∈ {execute, verify, decision-lock, pre-flight, pre-patch}])
```

Bei ratio > 4:1 (= >80% Reflection): WARN-Marker in state.json + advisor-Skill triggert "Lifecycle-Health-Alert" in nächstem Handover.

**Empirie-Anker:** p3-Pair Reflection-Round-Count (counter+re-sync+status+question) vs Action-Round-Count (decision-lock + ggf. execute) als Berechnungs-Beispiel.

**Self-Test:** T42 (synthetisches Pair mit ratio > 4:1 → WARN expected).
